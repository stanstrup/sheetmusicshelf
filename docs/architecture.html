Sheet Music Shelf Internals

9,600 lines of Python across 41 modules. The shape of it follows from one decision — that a file is not a catalogue entry — and one promise: a person's judgement outranks the machine's, permanently.

01The central idea

Most cataloguing tools assume one file is one item. Sheet music breaks that assumption immediately: a CD-ROM rip puts sixty pieces in one PDF, and an archive puts one concerto across eight. So the schema separates three things that other designs collapse into one.

graph LR
    C[Collection
a directory + its adapter] --> F[SourceFile
one PDF on disk]
    F --> P[Piece
a page range = one entry]
    P --> W[Work
the music itself]
    W --> K[Composer]
    P -.-> FC[FieldCandidate
every signal, kept]
    style P fill:#1F4E5F,color:#fff
    style W fill:#E3ECEE

Piece is the unit you browse: a page range inside a file, with its own title, composer and confidence. Work is the music, independent of how many copies you hold — it carries the canonical links, because an IMSLP page describes a sonata, not your particular scan of it. SourceFile is bookkeeping about a PDF: size, hash, page count, where its library copy lives.

The invariant everything else protects

A human decision permanently outranks a machine one. An accepted candidate short-circuits its field entirely: no combination of signals, no re-scan, no enrichment pass can replace it. Every feature that writes to the catalogue has to be checked against this.

03The ingest pipeline

One direction of flow, with a deliberate separation: the part that observes never decides, and the part that decides never reads files.

flowchart TD
    A[PDF on disk] --> B["pdfsignals.FileSignals
pages, hash, DocInfo, outline, text layer"]
    B --> C["Adapter.propose()
emits weighted Candidates"]
    C --> D["scoring.resolve_field()
fold, merge, noisy-OR"]
    D --> E["persist.commit_proposal()
store candidates, recompute"]
    E --> F{"route()"}
    F -->|≥ 0.80| G[accept]
    F -->|0.50–0.79| H[review]
    F -->|below, or conflict| I[hold]
    E --> J["library.materialise()
copy into the tree"]
    style C fill:#E3ECEE
    style D fill:#E3ECEE

FileSignals is the boundary. It holds what can be read from a PDF without interpretation — page count, SHA-256, DocInfo, the outline, whether there is a text layer, the stem and relative path. An adapter sees only this, never the filesystem, which is what makes adapters testable without fixtures on disk.

An adapter returns a FileProposal holding one or more PieceProposals, each a page range plus a list of Candidates. A candidate is an opinion: field, value, source name, weight. Adapters never resolve, never write, and never see the database.

Scoring turns competing opinions into one value with a confidence. Persistence stores every candidate and writes the resolved values onto the piece row for browsing and filtering.

04Adapters

A four-method protocol in ingest/adapters/base.py:

detect(root) -> float          # 0..1, how sure this adapter fits
prepare(context) -> None       # collection-wide defaults and notes
propose(signals, ctx) -> FileProposal
should_ignore(rel_path) -> bool

@register adds a class to the registry; choose_adapter() runs every detect and takes the highest score. The four in the tree differ mostly in where they find their evidence:

AdapterLinesReads
cdsheetmusic446DocInfo Subject strings like Mozart: Fantasia in F Minor, MOZ2, P1-10, plus per-volume tables of contents
sheetmusicarchive392Nothing but the path. Folder-to-form and filename-prefix tables; no metadata exists in these files at all
popcollection206Filenames of the form 348 - Artist - Title (v2).pdf
generic161Fallback: DocInfo and the PDF outline

Where domain knowledge lives

The lookup tables that encode musical fact — catalogue systems, composer name spellings, key names, which forms are numbered in sequence rather than by opus — live in music/, not in the adapters. Adapters hold conventions of one collection; music/ holds things that are true everywhere.

The dividing line has one deliberate exception. SINGLE_WORK_FOLDERS in the archive adapter names fourteen folders that hold one work split across files, because nothing in the file layout distinguishes grieg/con_amin (one concerto, three movements) from chopin/preludes (twenty-four separate preludes) — both are one stem plus a number. That is a judgement about the music, listed by hand, and it is scoped to the collection whose folders they are.

05Scoring

ingest/scoring.py is small and carries most of the risk. Four ideas, and one function.

combine() turns resolved fields into one confidence and the notes a reviewer sees. It is the only place the routing rules are written. They used to be written twice — once here and again in persist.recompute — and the copy that wrote to the database was missing the damaged-text rule, so a title of replacement characters auto-accepted in the catalogue while the tested path sent it to review. Anything deciding how far to trust a piece calls combine().

Folding

Values are compared after per-field normalisation, so Sonata No. 1, Sonata #1 and Sonata no.1 are one value rather than three competing ones. Titles get extra treatment: number words expand, and a title is subsumed by a longer one that contains it, so Children's Corner and Children's Corner, no. 1 merge rather than fight — with the longer, more specific string kept.

Noisy-OR

Independent sources agreeing should raise confidence without ever reaching certainty. Two sources at 0.7 combine to 0.91, not 1.4 and not 0.7. Weights are per-signal and stated in the adapter as named constants, so a reading's strength is visible where it is made.

Conflict caps rather than averages

When a field's second-place value carries more than CONFLICT_RATIO (0.55) of the winner's weight, that is disagreement, not noise. Confidence is capped at CONFLICT_CAP (0.45) — below the review floor — so a genuine conflict always reaches a person instead of being averaged into a plausible-looking number.

A piece is only as good as its weakest key field

Overall confidence is the minimum across composer and title, not the mean. A perfect title with an unknown composer is not an 0.9 piece.

One quiet subtlety. The scorer defends against a specific PDF fault: a font with no ToUnicode map decodes to a run of replacement characters. Their presence in a title means the text is damaged, not that the piece is misidentified, and the scorer treats it as such rather than as a competing reading.

06Candidates and their lifetime

Every signal ever offered about a piece is a row in field_candidate: field, value, source, weight, and whether a person accepted it. The piece row's own columns are a projection of those candidates, rebuilt by recompute() — which is what makes sms collection recompute possible without re-reading a single PDF.

Retirement

Candidates used to be append-only, on the reasoning that keeping every signal was the conservative choice. It was the opposite: a value an adapter had been fixed to stop emitting went on arguing its case for ever, so re-scanning with the fix changed nothing. Schumann's Kreisleriana stayed eight works because a stale Op. 16 no. 3 outlived the reading that produced it.

So each candidate records the adapter that made it. On a re-scan, that adapter's own unaccepted readings that it no longer makes are withdrawn — including a field it has stopped claiming altogether. Accepted candidates and anything posted through the curation API carry no adapter and are never touched, which is what keeps the invariant intact while still letting a bug fix take effect.

The matching projection rule: a field whose last candidate is gone is cleared from the piece row rather than left standing. Otherwise an adapter could withdraw a reading and the value it produced would still show in the catalogue — and still group works by it.

Agents get the same right through POST /curation/retractions. Retirement is scoped to the adapter that made a reading, so a candidate posted through the API — which has no adapter — was permanently unretirable: one wrong value at 0.65 conflicts with the right one, caps the field at 0.45, and holds the piece for good. An agent has to be able to be wrong reversibly. A decision is not a proposal and is never withdrawn this way; correcting one means accepting a different value, which stays on the record as its own decision.

07The data model

Fifteen tables. The interesting ones:

Free-form structures — notes, tags, annotation geometry — are JSONB. Everything filtered or sorted on is a real indexed column. Notes are split in two on purpose: notes_ingest is what the adapter observed and survives every recompute; notes_machine is what the scorer concluded and is rebuilt each time, because storing a derived note would duplicate it on the next pass.

08The managed library

library.py owns the tree. target_path() builds <Composer>/<Title> (<Cat.>)/<file>.pdf for single-work files, and _Books/<Collection>/<original path> for volumes holding several pieces — a 378-page anthology cannot sit in one work's folder without misrepresenting itself.

Because a folder name is built from metadata, it must follow the metadata. Three functions exist for that:

  • _refile() — moves a copy the library already holds when review renames it, rather than copying again and leaving a folder behind for every name a piece ever had
  • _prune_empty() — removes folders a move emptied, stopping at the library root; a composer folder left behind after their last piece moved out reads as a piece still being there
  • _claimed_by_another() — stops two catalogue rows sharing one file. Size is not identity: the pop collection holds the same arrangement twice under different numbers, and matching on size alone let the second row point at the first row's copy and never get one of its own

resolve_source() is the one way to find a file: the library copy when there is one, the original otherwise. Three call sites used to resolve three ways, and the odd one out built its path from the collection's source directory — which stopped being mounted when the library became authoritative, so that endpoint returned 410 for the whole catalogue while the page renderer, reading the same rows, worked.

The drop folder is the same machinery pointed at a queue. ingest_collection() owns it, clear_ingested() empties it — checking the copy actually on disk rather than the database, because removing something from a drop folder is only safe once the library really holds it.

Filesystem work is not covered by the transaction. A failure part-way through a materialise or a retirement rolls the database back but leaves completed unlink and move calls done. This has already happened once in anger. The tree can always be rebuilt from the originals, so it is recoverable — but the counts a run reports can disagree with the counts in the database, and that is why.

09Web, API and auth

Two surfaces over one core. web.py serves server-rendered HTML with plain forms — no client framework, no CDN assets, because a phone on the VPN may have no route to the internet. It is the largest module and the most obvious candidate for splitting.

api/ is the machine surface under /api/v1: catalogue search and facets, collections and scans, composers and portraits, curation, page images, shelves, annotations. External curation tools are a first-class client — the app deliberately runs no model itself, so the API is how a model outside it contributes.

Three ways in, resolved into one viewer: an authentik OIDC session for people, a bearer token with scopes for agents and devices, and an open mode for local development. Curation endpoints accept a candidate with a weight as well as an outright decision, which is usually the more honest thing for a machine to offer.

A trap worth remembering. FastAPI runs a yield dependency's exit code after the response is sent, so a session committed on the way out lands after the browser has already followed a redirect. Every mutating handler therefore calls commit_now() before redirecting. Without it the review page reproducibly showed stale state until a manual refresh.

10Jobs and rendering

The queue is a table. claim_one() takes a job with FOR UPDATE SKIP LOCKED, handlers register by kind through a decorator, and the worker loops. Adding Redis to a stack that already runs PostgreSQL would be a second thing to operate for no gain at this size.

A worker killed mid-job leaves it running with nothing to notice: no lease, no heartbeat, and the row lock dies with the connection. reclaim_stale() returns jobs stuck past four hours to the queue, and fails one that has killed three workers rather than retrying for ever. Filing is a job too, queued (deduplicated) when review changes a name, because the library folder is named from that metadata and letting the tree drift is letting the catalogue lie about where things are.

The worker also yields to the machine: wait_for_headroom() pauses between files while the one-minute load average is above SMS_LOAD_CEILING. On a four-core box carrying dozens of containers, a scan that ignores load is not a slow scan — it is an outage for everything else.

Rendering goes through render.py: pages to WebP at 320, 800, 1200 and 1800, cached under a key derived from the file's content hash, so an unchanged file reuses renders across re-scans and an edited one gets fresh images automatically.

PDFium is not thread-safe. A module-level lock serialises every render. This was learned by rendering sixty thumbnails in parallel and corrupting the library process-wide. Do not remove the lock to make thumbnails faster.

11Enrichment and throttling

Three passes, all outbound, all optional. Composers resolve Wikidata-first and fall back to Wikipedia, caching the portrait locally with its attribution. Works match against IMSLP's MediaWiki API and MusicBrainz's /ws/2 with Lucene queries built from the catalogue number and composer. Years are read from the IMSLP page already linked, which costs one extra read rather than another search — and the source's own wording is kept alongside the parsed integer, because reducing "ca. 1783" to 1783 would promise precision the source did not give.

Matching handles compound catalogue citations in both directions: MusicBrainz files Mozart's first sonata as "K. 189d/279" and IMSLP as "K.283/189h", and either half counts. Fixing that alone took MusicBrainz coverage from 35 works to 57.

Everything outbound passes enrich/throttle.py: a per-host gate with a minimum interval — 1.2 s for MusicBrainz, 0.6 s for IMSLP, 0.2 s for Wikimedia — and a circuit breaker that stands the app down when a service starts refusing. config.user_agent raises if SMS_CONTACT is unset rather than sending a plausible-looking fake, because these services block clients without a reachable contact and being polite is a correctness property here, not a courtesy.

12Tests and migrations

308 tests, 2,253 lines. Most are pure — adapters take a FileSignals dataclass, the scorer takes a list of candidates, catalogue and key parsing take strings — which is why the suite runs in seven seconds and why the parts with the subtlest logic are the easiest to test.

That was the whole strategy until an independent review found what it was hiding. score_piece and persist.recompute had drifted into two versions of the same rules, and only score_piece was tested: a rule was asserted, was real, and never ran on the path that writes to the catalogue. Nothing pure could have caught it, because the fault was in the seam between two tested things.

So there is now a conftest.py with a PostgreSQL fixture — the models use JSONB and the queue uses FOR UPDATE SKIP LOCKED, so SQLite would be testing something else — pointed at a scratch database by SMS_TEST_DATABASE_URL, and skipped rather than failed when none is reachable, so a checkout with no database still runs the rest. Three files cover the seams: test_persistence.py (routing, the human-outranks-machine promise, retirement, tombstones, retraction), test_jobs.py (claiming, reclaiming, queueing once) and test_routes_smoke.py, which calls every page and read endpoint once and asserts only that they answer — twenty lines that would have caught the 410.

Thirteen Alembic migrations. A column added to a populated table gets a server_default first and the constraint after; a data backfill belongs in the migration that needs it, as with attributing existing candidates to the adapter that made them.

13Sharp edges

Things that will bite someone changing this code.

  • Commit before redirecting. See §09. It looks like a caching bug every single time.
  • Hold the PDFium lock. See §10.
  • Filesystem operations are not transactional. See §08 — and run sms verify after anything that moves files in bulk, because that is the only way to find out.
  • Weights are magic numbers spread across adapters as named constants. Readable in place, but there is no global view of how they interact and no test asserts the ordering between them.
  • Adding a candidate field means touching KNOWN_FIELDS, possibly DENORMALISED, possibly _INT_COLUMNS, and a migration. There is still no single place that declares a field. Adding a filter, by contrast, is now one field and one line in catalog_query.py.
  • A file with more than one piece is a "book" and files under _Books/. Anything that changes how many pieces a file has changes where it lives on disk.
  • Adapters must stay pure. They see FileSignals and a context, never the database and never the filesystem. Reaching outside that is what makes them untestable.
  • Instrument and PieceInstrument are unused. Instrumentation is a denormalised string on the piece, because a folder called violpian says "violin and piano" and nothing finer. A normalised model should wait for evidence that supports one.

Not a sharp edge: web.py's length. It reads as a flat list of about twenty-five independent handlers averaging thirty lines, and an outside review of this codebase concluded that splitting it buys tidiness and nothing else. The one thing worth extracting from it was the query builder it duplicated with the API, and that has been done.
