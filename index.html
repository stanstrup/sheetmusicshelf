Features

Built for serious libraries

Built around the actual workflows of a practising musician.

Faceted browse

Filter by composer, period, form (sonata, étude, waltz…), instrumentation, key, or collection — combinations narrow the results live without a page reload. A search bar handles composer names and titles. Sort by composer, title, or cataloguing confidence.

In-browser reader

PWA reader — install it to your home screen and it works offline. Annotations (pen, highlighter, eraser) are stored per page and survive refreshes. Two-up mode pairs facing pages. A screen-awake toggle keeps the tablet lit while you play. Fullscreen hides the OS chrome entirely.

Canonical enrichment

Works are matched to MusicBrainz by catalogue number — K. 331, Op. 67, BWV 1004 — using the one identifier that survives every publisher's retitling. Composition year is fetched from the linked IMSLP page. Composer portraits and bios come from Wikidata, cached locally.

Composer pages

Each composer gets a page with their Wikidata portrait (with attribution), birth–death years, historical period, a Wikipedia excerpt, and a scrollable grid of every piece in the library. Links back to the filtered browse view for deeper faceting.

Shelves

Ordered collections — a practice setlist, a concert programme, a teaching sequence. A shelf is a playlist, not a tag: pieces have positions and can appear on multiple shelves. Add from any piece page; reorder in the shelf view.

Curation API

All cataloguing metadata — title, composer, key, form, catalogue number — is writable through a documented HTTP API with token auth. Use an external LLM to suggest metadata; you review each proposal and accept or reject it. The app never calls a model itself.

Ingest & review queue

Drop new PDFs into the ingest folder (Calibre-style) and click Import from ingest folder in Settings. The scanner extracts bookmarks and text, proposes a title, composer, key, and form, and scores its own confidence. Pieces above the auto-accept threshold are accepted automatically; the rest land in the review queue.

Docker-native

Ships as a single image: app, worker, and Postgres in one compose file. OIDC via authentik for household SSO; falls back to a shared password. Backup labels for nautical-backup. Worker throttles itself against the host's load average so your other 40-odd containers stay responsive.

Setup

Up in five minutes

Runs on any Docker host with a shared music folder. The compose file is self-contained.

1

Prerequisites

Docker Desktop with WSL2 integration enabled. The library bind mounts are /mnt/z/Books/SheetMusic-style paths that only resolve from inside WSL — run docker compose up from there, not from PowerShell.

Postgres runs as a sidecar (no external instance needed). The cache volume holds thumbnails and extracted text; it's a named Docker volume rather than a CIFS mount because thousands of small files over SMB are slow.

2

Download the starter pack

Grab the latest release from GitHub. Extract into your compose directory (e.g. Z:\docker\compose\). You get two files:

  • sheetmusicshelf.yml — the full compose stack
  • .env.example — secrets template; rename to .sheetmusicshelf.env
Download starter pack →
3

Fill in the env file

Rename .env.example to .sheetmusicshelf.env and set at minimum:

.sheetmusicshelf.env 
# Required — signs the session cookie
SMS_SECRET_KEY=<generate with: python -c "import secrets; print(secrets.token_urlsafe(48))">

# Required before any MusicBrainz or IMSLP lookup
SMS_CONTACT=you@example.com

# Authentication: shared password for households without an IdP
SMS_PASSWORD=correct-horse-battery-staple

# --- or OIDC (wins over SMS_PASSWORD when both are set) ---
# SMS_OIDC_CLIENT_ID=
# SMS_OIDC_CLIENT_SECRET=
# SMS_OIDC_ISSUER= (set in the compose file as SMS_OIDC_ISSUER)

# Database password — must match POSTGRES_PASSWORD in .sheetmusicshelf-db.env
# SMS_DATABASE_URL=postgresql+psycopg://sms:YOURPASS@postgres-sheetmusicshelf:5432/sms

Create .sheetmusicshelf-db.env with just POSTGRES_PASSWORD=YOURPASS (matching the URL above).

4

Edit mount paths and bring it up

Open sheetmusicshelf.yml and adjust the volume paths to match your library location. Then from WSL: 

docker compose -f sheetmusicshelf.yml up -d

The web service runs the Alembic migrations automatically before it starts serving. The worker waits for the web service to be healthy before it starts processing — so there's no race condition on the first run.

5

Register a collection and scan

A collection is a root directory the scanner indexes. Register one, then scan it. New files are proposed with a confidence score; accepted pieces go into the library. 

# Register the collection (once)
docker exec sheetmusicshelf sms collection add /library/managed --name "My Library"

# Scan — proposes new pieces from the directory tree
docker exec sheetmusicshelf sms collection scan 1

# Review the queue in the browser, then accept or reject
# Or: drop PDFs in /library/ingest and click Import in Settings

The worker runs enrichment (thumbnails, MusicBrainz, Wikidata) in the background after each scan. It throttles itself while the host's 1-minute load average is above SMS_LOAD_CEILING.

6

Add a reverse proxy

The app listens on port 8014. Point a reverse proxy (Nginx Proxy Manager, Traefik, Caddy) at it and give it a hostname. Set SMS_BASE_URL in the compose file to the public URL — it's used for OIDC redirects and the service-worker scope.

sheetmusicshelf.yml (excerpt) 
environment:
  SMS_BASE_URL: https://sheetmusic.example.org

Configuration

Environment reference

All settings are environment variables — no config file needed.

Variable Default Description
Authentication
SMS_SECRET_KEY required Signs the browser session cookie. Generate with python -c "import secrets; print(secrets.token_urlsafe(48))"
SMS_PASSWORD Shared password for the whole library. Ignored when OIDC is configured.
SMS_OIDC_ISSUER OIDC issuer URL (e.g. authentik). Wins over SMS_PASSWORD when set together with the client credentials.
SMS_OIDC_CLIENT_ID OIDC client id from your identity provider.
SMS_OIDC_CLIENT_SECRET OIDC client secret.
Paths
SMS_MANAGED_ROOT /library/managed The catalogued library tree. Mount your music collection here read-write.
SMS_INGEST_ROOT /library/ingest Drop folder for new PDFs. Files here are moved into the managed tree on sms ingest --apply.
SMS_CACHE_ROOT /cache Thumbnails and extracted text. Use a named Docker volume — CIFS is too slow for thousands of small files.
SMS_APK_ROOT /library/managed/_app Where a published Android APK is served from, so tablets can install from the same server.
Cataloguing thresholds
SMS_AUTO_ACCEPT 0.80 Confidence score above which proposals are accepted automatically without going to the review queue.
SMS_REVIEW_FLOOR 0.50 Minimum confidence score to show a proposal in the review queue. Below this it is discarded.
Worker behaviour
SMS_LOAD_CEILING 6.0 The worker pauses between files while the host's 1-minute load average is above this. Set to 0 to disable (not recommended on shared hosts).
Networking & identity
SMS_BASE_URL http://localhost:8000 Public URL of the app. Used for OIDC redirect URIs and the service-worker scope. Set to your reverse-proxy hostname.
SMS_CONTACT required for enrichment Email address or project URL. MusicBrainz requires a reachable contact in the User-Agent and blocks clients that omit one.
SMS_DATABASE_URL postgresql+psycopg://sms:sms@localhost/sms SQLAlchemy-format Postgres connection string. The compose file sets this via .sheetmusicshelf.env.

CLI quick reference

The sms command runs inside the app container. All subcommands accept --help.

# Collection management
sms collection add /library/managed --name "Mozart Complete Piano"
sms collection scan <id>          # propose new pieces
sms collection list

# Ingest drop folder — use Settings > Import in the web UI instead
# sms ingest --apply              # (CLI fallback: move files, register pieces)

# Composer authority records
# Use the Enrich from Wikipedia button on a composer page instead
# sms composer enrich             # (CLI fallback: fetch Wikidata portraits + bios)
sms composer list

# Work authority records + canonical links
sms work years                    # back-fill composition years from IMSLP
sms work list

# Database
sms db upgrade                    # run pending migrations (done automatically at startup)
sms db url                        # show configured database URL (password masked)

Android companion

Read on the stand

A native app for your tablet. Marks you draw sync with the web reader instantly.

Browse & filter

Search by title, composer or catalogue number. The same facets as the web — period, form, key — with counts that update as you type.

Swipe through pages

One page per swipe, rendered at the full width of your screen. The display stays awake — a reader that sleeps mid-piece when both hands are busy is worse than none.

Annotate with pen & highlighter

Marks are stored as fractions of the page box and sync to the server the moment a stroke finishes. Open the same piece in the browser and the marks are already there, in the same position on every screen size.

Token auth, no password

The app authenticates with a token scoped to catalog:read (browse and read) and optionally catalog:write (save marks). Tokens are independent of how people sign in to the browser.

Installing

  1. Get the APK. Download app-release.apk from the latest release, or open http://your-server:8014/app on your tablet — the server hosts the current build and shows a one-tap install button.
  2. Make a token. Open Settings in the web interface and press Make a token. Or from a shell inside the container:
    shell 
    docker compose -f sheetmusicshelf.yml exec sheetmusicshelf \
  sms token create "tablet" --scope catalog:read --scope catalog:write
    The token is shown once and never stored in plain text.
  3. Configure the app. On first launch it goes straight to Settings. Enter your server address (e.g. 192.168.1.10:8014) and the token, then press Save and test.

The app permits cleartext HTTP because the server lives on your LAN or VPN. Blocking it would make it useless in exactly the setting it was built for.
